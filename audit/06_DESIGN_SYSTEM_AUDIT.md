# 06 — Design System Audit

*வண்ணங்களும் எழுத்துருவும் ஒரு முறைமை ஆக — tokens, inspected directly, not assumed.*

## What exists today (VERIFIED)

- **Token source of truth**: `app/src/styles/tokens.css` (CSS variables) mirrored by `app/src/theme/tokens.ts` as TS constants referencing `var(--x)` (lines 1-70+). This is a sound single-source pattern: change the CSS variable once, both light/dark themes and every inline-styled component pick it up.
- **Theme switching**: `data-theme="dark"` attribute on `<html>` (comment, `tokens.ts:5-6`); `app/src/state/theme.ts` manages it (not opened in depth — confirm persistence mechanism separately).
- **Color palette layers found in `tokens.ts`**: a maroon/cream heritage palette (`maroon`, `page`, `card`, `hairline`, tier colors `sprout/root/palmyra`) matching PROJECT.md's original design doc, **plus** a second, parallel "Material-3 style" semantic set (`primary`, `primaryContainer`, `onPrimaryContainer`, `secondary`, `tertiary`, `surfaceVariant`, lines 50-62, explicitly commented "NorthNadu semantic set (Material-3 style names)"). Both sets are live in the same file.
- **Typography**: three font families via `font.ui`/`font.head`/`font.ta`/`font.mono` tokens (referenced throughout `Home.tsx`), matching PROJECT.md's Noto Sans Tamil / Inter / JetBrains Mono spec.
- **No Tailwind, no CSS-in-JS library, no component library (MUI/Chakra/etc.)** — confirmed by absence in `app/package.json` dependencies review during exploration and by the inline-`style={{}}` pattern used pervasively in `Home.tsx` and `BottomNav.tsx`.
- **Shared primitives**: `app/src/components/ui.tsx` (345 lines) — `QueryBoundary` and presumably `Button`/`Chip`/`Card`/`Toggle` etc. per README's own description (`README.md`: "Button, Chip, Card, Toggle, StatusPill, TierBadge, LabelPair, EmptyState"). Not all primitives individually verified in this pass, but their existence as a shared module (rather than per-screen duplication) is itself a strength signal.

## What's reusable vs. what needs rework (for 07's redesign strategy)

**Reusable as-is**: the CSS-variable token architecture, the light/dark switching mechanism, the `QueryBoundary` loading/error pattern, the bilingual label-pair convention, the PWA/service-worker setup, the cookie-based auth security model.

**Needs rework before scaling**: the dual color-naming system (DS-01), the dual localization system (DS-02), ad hoc hardcoded colors in Home's quick-access grid (DS-04), and the IA overlap between Home's Quick Access grid and the Community bottom-tab hub (see 05, UX-05).

## Recommended token system direction (not yet built — proposal only)

1. Pick the Material-3-style semantic naming (`primary`/`primaryContainer`/`secondary`/`tertiary`/`surfaceVariant`) as canonical, since it is the newer addition and names intent rather than a specific brand hue — this scales better across a rebrand than `maroon`/`sprout` literal names.
2. Re-point the tier-accent colors (`sprout`/`root`/`palmyra`) to semantic roles (`tierLevel1`/`tierLevel2`/`tierLevel3`) so a future tier rename (as already happened once, per DS-03) doesn't require touching color tokens.
3. Fold `useWorkspaceText()` into i18next as its implementation detail (e.g. have it read from the same JSON resource bundle) rather than maintaining inline string literals in components.
